# 多目标优化排程

## 概述

系统支持基于4个目标的多目标优化排程：

1. **交期优先** - 最小化订单延期
2. **设备利用率** - 提高设备使用效率
3. **最小换产** - 减少设备换产次数
4. **最小完工时间** - 缩短总完工时间

用户可以通过调整权重来平衡这些目标，系统会自动找到最优的排程方案。

---

## 目标详解

### 1. 交期优先 (Due Date Priority)

**目标**：最小化订单延期惩罚

**计算方式**：
```python
延期惩罚 = Σ(订单权重 × max(0, 完工时间 - 交期))

订单权重 = 优先级 × (2 if 急单 else 1)
```

**特点**：
- 优先级越高（数字越小）的订单，延期惩罚越大
- 急单的延期惩罚加倍
- 提前完成不会获得奖励，只惩罚延期

**适用场景**：
- 客户对交期要求严格
- 有明确的优先级区分
- 延期会造成重大损失

**权重建议**：
- 高（1.5-2.0）：交期是首要考虑
- 中（0.8-1.2）：平衡交期和其他目标
- 低（0.0-0.5）：交期不是主要关注点

---

### 2. 设备利用率 (Equipment Utilization)

**目标**：提高设备使用效率，减少空闲时间

**计算方式**：
```python
通过最小化 makespan 来间接提高利用率

利用率 = 实际工作时间 / (排程天数 × 每日工作时长)
```

**原理**：
- makespan 越小，相同工作量下设备利用率越高
- 鼓励紧凑的排程，减少设备空闲

**特点**：
- 间接优化，通过压缩时间提高利用率
- 与最小完工时间目标部分重叠
- 有助于发现瓶颈设备

**适用场景**：
- 设备投资成本高
- 希望最大化产能
- 设备数量有限

**权重建议**：
- 高（1.0-2.0）：设备利用率是关键指标
- 中（0.3-0.8）：平衡利用率和灵活性
- 低（0.0-0.3）：允许设备有较多空闲

---

### 3. 最小换产 (Minimize Changeover)

**目标**：减少设备在不同订单间的切换次数

**计算方式**：
```python
换产次数 = Σ(设备上连续执行不同订单工序的次数)

对于设备k上的工序i和j：
  if (订单i ≠ 订单j) and (都在设备k上执行):
    换产次数 += 1
```

**特点**：
- 鼓励同一订单的工序集中在一起执行
- 减少设备调整和准备时间
- 降低换产带来的质量风险

**适用场景**：
- 换产时间长或成本高
- 需要清洗、调整设备
- 不同产品差异大

**权重建议**：
- 高（1.0-2.0）：换产成本很高
- 中（0.3-0.8）：有一定换产成本
- 低（0.0-0.3）：换产影响较小

**注意**：
- 过高的换产权重可能导致某些订单延期
- 需要与交期目标平衡

---

### 4. 最小完工时间 (Minimize Makespan)

**目标**：缩短从开始到所有订单完成的总时间

**计算方式**：
```python
makespan = max(所有工序的结束时间) - min(所有工序的开始时间)
```

**特点**：
- 经典的排程优化目标
- 提高整体效率
- 缩短交付周期

**适用场景**：
- 希望快速完成所有订单
- 提高生产周转率
- 减少在制品库存

**权重建议**：
- 高（1.0-2.0）：快速完成是首要目标
- 中（0.2-0.8）：平衡速度和其他因素
- 低（0.0-0.2）：允许较长的完工时间

## 目标冲突与权衡

### 常见冲突

#### 1. 交期 vs 换产
- **冲突**：满足紧急交期可能需要频繁换产
- **权衡**：根据换产成本和延期损失调整权重

#### 2. 利用率 vs 交期
- **冲突**：高利用率可能导致某些订单延期
- **权衡**：预留适当的缓冲时间

#### 3. 换产 vs 完工时间
- **冲突**：减少换产可能延长总完工时间
- **权衡**：评估换产节省的时间是否值得

### 权衡建议

| 场景 | 建议权重配置 |
|-----|------------|
| 有紧急订单 | 提高 due_date 权重 |
| 设备产能紧张 | 提高 utilization 权重 |
| 换产成本高 | 提高 changeover 权重 |
| 需要快速交付 | 提高 makespan 权重 |
| 订单差异大 | 降低 changeover 权重 |

## 数学模型

### 目标函数

```python
Minimize: 
  w1 × 延期惩罚 + 
  w2 × makespan + 
  w3 × 换产次数 + 
  w4 × makespan

其中：
  w1, w2, w3, w4 为用户设置的权重
```

### 归一化处理

由于不同目标的数量级差异很大，系统会自动进行缩放：

```python
# 延期惩罚：分钟级别，乘以10000
延期项 = w1 × 10000 × 延期惩罚

# 利用率/makespan：分钟级别，乘以1
利用率项 = w2 × 1 × makespan

# 换产次数：个数级别，乘以1000
换产项 = w3 × 1000 × 换产次数

# 完工时间：分钟级别，乘以1
完工时间项 = w4 × 1 × makespan
```

这样可以确保各目标在相同权重下有相近的影响力。

## 技术实现

### 约束规划求解器

使用 Google OR-Tools CP-SAT 求解器：

**优势**：
- 支持多目标优化
- 高效的约束传播
- 能找到全局最优解（在时间限制内）

**限制**：
- 求解时间随问题规模增长
- 当前限制：60秒

### 换产检测

```python
# 对于设备k上的工序i和j
if (订单i ≠ 订单j) and (都在设备k上执行):
    # 创建换产变量
    changeover_var = BoolVar()
    
    # 约束：changeover = presence_i AND presence_j
    model.Add(changeover_var >= presence_i + presence_j - 1)
    model.Add(changeover_var <= presence_i)
    model.Add(changeover_var <= presence_j)
```

### 延期计算

```python
# 订单完工时间
order_completion = max(订单所有工序的结束时间)

# 延期时间
tardiness = max(0, order_completion - due_time)

# 加权延期惩罚
weighted_tardiness = priority × (2 if urgent else 1) × tardiness
```

## 常见问题

### Q1: 为什么调整权重后结果变化不大？

**可能原因**：
1. 约束太严格，可行解空间小
2. 其他目标的权重过高
3. 问题规模小，优化空间有限

**解决方法**：
- 检查约束是否合理
- 尝试更大的权重差异
- 增加求解时间限制

### Q2: 如何处理目标冲突？

**建议**：
1. 明确业务优先级
2. 量化各目标的重要性
3. 进行多次试验找到平衡点
4. 考虑分阶段优化

### Q3: 权重设置有最佳值吗？

**答案**：
没有通用的最佳值，取决于：
- 业务特点
- 订单特征
- 设备状况
- 成本结构

建议根据实际情况调整。

### Q4: 能否只优化一个目标？

**可以**：
将该目标权重设为非零，其他设为0：

```python
# 只优化交期
{
    'due_date': 1.0,
    'utilization': 0.0,
    'changeover': 0.0,
    'makespan': 0.0
}
```
